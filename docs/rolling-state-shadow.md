# 按日滚动状态影子实验

独立研究入口，不接入活动路由，不覆盖 Current/Test、旧冻结、模型工件或注册表。源码基础为 `20467d2e2e9adec6c98ada7520926b5518e65b9e`。

## 实验协议

- 两轨使用现有 M2 Poisson 强度核心，固定 half-life=365、ridge=30，不选权重或重新选择配方。这不是生产 Current/Test 对照，也不是人工综合选分。
- FIXED_STATE 在共同起点锁定已核验历史；DAILY_ROLLING 此后按日重拟合。各队列独立，两轨目标名单、赛果和缺项分母一致。
- 每个 UTC 比赛日使用统一状态和预先固定的时点，默认 UTC 00:00（北京时间08:00）。只有比赛日期严格早于当前日、且90分钟赛果已经实际采集/导入的数据进入滚动状态。当天早场结束不能改变晚场预测。
- 不用比赛日期推定结果可用时点，不将现在采集的历史数据倒填为当年已知。延迟到达和赛果修订只在其实际可用的后续批次生效。
- 目标输入白名单隔离比分、xG、过程等赛后字段。模型没有加入xG、首发、市场或人工改分。
- 目标/赛果结算同时核对队列、赛事、日期、球队及开球时间，不仅凭比赛ID。缺少截止前赛程证据则两轨同时ABSTAIN，保留已观察范围分母。
- 实际盘口缺资料记NA，不用固定2.5球代替实际盘口。

## 运行与验证

使用Python3.12和项目固定依赖。原始采集适配器只支持上述两个联赛；通用replay可接受其他已核验队列，但不能因此宣称杯赛阶段已经验证。每次输出路径必须不存在。

```bash
python runtime/research/rolling_capture_input.py \
  --state-dir /path/to/data-repository --cohorts aus.1 jpn.1 \
  --start 2026-11-05 --end 2026-11-09 \
  --evaluation-at 2026-11-10T16:00:00+00:00 --out /new/replay-input
python runtime/research/rolling_state.py \
  --input /new/replay-input/input.json --out /new/replay-input/replay.json
python -m unittest discover -s runtime/research -p 'test_rolling*.py' -v
python scripts/check_repository.py
python scripts/run_tests.py
```

22项专项回归覆盖同日/未来标签污染、延迟采集、修订、缺时点、非90分钟数据、跨队列污染、顺序置换、固定轨不变、配对ABSTAIN、目标身份、未来赛程不能改变截止时间和完整分母。合成测试数据仅检验程序契约，不作为效果证据。

独立审查发现并修复过“后来捕获的赛程反向影响日时点”和“仅凭ID结算、不核完整身份”问题。初版4场结果已作废，只采用修复后3场版本。
