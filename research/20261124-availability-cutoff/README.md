2026-11-24 的档案核验中，11 月 22 日九项联赛的 30 场首版有 4 场预计换门将，其中 3 场的同一供应商也将常用门将列入缺阵名单。留存的赛事方、俱乐部材料能在同一截止前确认其中 **0 场**。本轮配对预测分母为 0，第一比分、实际展示三比分、90 分钟胜平负、实际盘口大小球和精选三场均无新增可评分预测。当前阶段一的目标继续为 20%、40%、65%、70%，精选三场第一比分另计。

## 一次检查三个时钟

采用首份综合赛前版本已有的截止、固定开球前 60 分钟和固定开球前 15 分钟。主比较使用共同 T−60，T−15 单列。截止相等时可用，截止必须早于开球。原件接收完成时间、来源自报发布时间、资料写入冻结的时间分别记录。协议于 11 月 24 日 07:50:04 UTC 在本地登记，早于本次按角色核验。11 月 22 日赛果此前已知，本轮只检查当时的输入。协议及回放均未建立新的前瞻队列。[协议](protocol.json)

单一数值假设为“本场官方确认的首发门将与本队常用门将不同”。常用门将要求同赛事此前六场中至少首发四次。既要能证明历史角色，也要能证明目标场在截止前的状态。单侧正式缺席通告可以提示换人，未署名、未指明场次、受罚范围不清或无法绑定球员 ID 的材料均保留为未知。若日后有足够覆盖，须在更早的开发窗口和后续独立窗口预先固定同场同截止的基线与候选，纳入换将和未换将场次。

## 离线复现

在源码仓根目录，Python 3.11 或更高版本并装好项目依赖。下列大写参数由持有归档的人指定。所有输出写入另设的研究目录。共享发布流程、模型训练、供应商客户端均不参与。

```sh
export PYTHONPATH=runtime
D=research/20261124-availability-cutoff
python -m unittest discover -s "$D" -v
python "$D/audit_archives.py" --data "$DATA_GIT" --freezes "$FIRST_COMPREHENSIVE_LEDGER" --jcup "$JCUP_PACKET" --out "$AUDIT_OUT"
python "$D/club_packet.py" --packet "$OCT11_REPORT_DIR" --out "$AUDIT_OUT"
python "$D/slate_roles.py" --archive "$NOV22_ARCHIVE" --receipts "$NOV22_RECEIPTS" --out "$AUDIT_OUT"
python "$D/people_evidence.py" jleague --fixture "$TARGET_FIXTURE_JSON" --receipt "$JCUP_PACKET/staging/sources.json" --receipt-sha256 a3329e71c51abc244bb2e8b89c065b00e49e71401e9c33ee1be527149babec28 --raw "$MATCH_PAGE_HTML"
python scripts/run_tests.py --layer integration
```

`DATA_GIT` 需包含数据提交 `a6d45024cf6cf622f05e4b378ab53cfe2d6ae329`。`NOV22_ARCHIVE` 和 `NOV22_RECEIPTS` 是数据提交 `87e3ad5ba551714dbf840bae84335d3bf619a50a` 中 `workspace-updates/20261122-covered-slate/` 的 `evidence.tar.gz` 和 `receipts.json`。`JCUP_PACKET` 是原日联杯归档中的 `jcup-lineup-20261111`。中央首冻目录和 10 月恢复包需要另外持有，逐文件和原台账指纹见汇总。只用公开源码即可执行 19 条合成回归，真实档案回放需要对应原件。严格集成另外需要注册表匹配的本地研究资产。

单场预检输入沿用 fixture 的 `match_id / competition / home / away / kickoff_at / cutoff_at`。日联杯另带 `stage / leg`。ESPN 使用标准请求记录，FotMob 使用指向原始 URL 的取回时间和 SHA，并核联赛及常规赛范围。预检在标准输出分别给出三个时钟的状态、是否已到该时刻以及球员角色可用性。用独立归档登记的回执摘要核对元数据，单独对刚生成的回执重新计算摘要不能证明其在历史截点已存在。对外只保留汇总及原件指纹，逐场回放自行在本地生成。
