# 所有后续分析默认冻结

用户授权：2026-10-15，北京时间。此规范优先于旧文档中“研究预测不作为冻结”的约定。冻结是保留实际发布内容，不代表模型已验证、晋级或达到准确率目标，也不重新注册原500+200实验。

- 后续每次分析在发布前保存原文、实际计算输出、比赛身份、开球时间、数据截止时间、版本和来源；真实矩阵有则原样保存，缺失明确标记，不补造。待定、拒绝预测也留档。
- 当前模型与test模型始终并行、独立推荐和复盘；入口保存完整双模型快照。综合人工判断以独立轨道保存，不覆盖任一模型。不能用任意轨道中较好的结果替代原推荐。
- 首次分析、首发后更新和临场更新分别追加版本，不覆盖旧记录。每条有冻结ID、北京时间、内容哈希及前一版本哈希。修改冻结文件会使完整性核查失败；本地文件不等于异地备份或平台持久性保证。
- 赛前、滚球、复盘分别标记。赛前冻结必须在开球前完成；不倒填时间，不将缺失的历史预测追认为冻结。每份回复显示冻结ID和时间，保存失败不得称为已冻结。
- 每场、每条模型轨道首次赛前发布版本为默认主评价版本。更新另列对照，不重复增加独立比赛分母，不赛后挑选最佳版本。双模型配对快照中的两个模型各自统计；人工轨道另计。待定/失败保留总覆盖分母，不算有效比分命中。版本及冻结时间不符合条件的不纳入赛前指标。
- 最高指标仍是未来真实冻结Primary Top1；胜平负和实际盘口大小球单独复盘，五种大小球结算分别统计。新冻结可供未来逐轨评价；旧研究评估器的formal_kpi_eligible=false为其原实验资格，不能解释为新记录未冻结，也不能擅自改成模型晋级证明。

## 实际入口

默认双模型命令现已自动保存冻结，再写输出文件；默认赛前，滚球必须显式指定`--stage live`：

```bash
python runtime/predict_active.py fixture.json --out new-pair.json
```

综合文字、待定和复盘使用下面入口；输入JSON含`fixture`及`payload`。fixture必须有match_id、带时区kickoff_at和cutoff_at。payload保存实际发布原文、版本、来源与缺项，不得放密钥。每场分开保存，人工研究固定使用`comprehensive`轨道，不因结论变化新建轨道逃避版本约束。

```bash
python runtime/research/analysis_freeze.py analysis.json --stage prematch --track comprehensive
```

阶段可选prematch、live、review。默认目录`/workspace/WCPP/forecasts/issued-analyses`，可用`--root`指定保存位置。程序内纯计算`run()`仍无写盘副作用，不可单独将其输出称为冻结；使用CLI或显式调用save后取得回执。旧台账保持原样与可读性，新记录不自动导入旧评估器。
