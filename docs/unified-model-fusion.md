# 当前仓库统一融合入口

2026-11-02按用户请求实现：按活动注册表为同场运行当前/test，然后输出独立融合比分矩阵，保留原模型、原工件、原矩阵与综合推荐。适用于注册表所支持的队列和真实未来输入；不把19个联赛模型全部平均来预测一场比赛。

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
python runtime/fuse_models.py /absolute/fixture.json \
  --out /absolute/NEW-unified-prediction.json
```

可用`--registry`显式选择经核实的资产；默认仍是原19队列注册表，不自动覆盖incoming冲突副本。程序实际调用`predict_active.run`，因此原有MAIN/ML、J1/K1、澳超、亚冠等路由由原注册表分派，不另写一套不一致的基础模型。

输出包含`current_test_pair`和`fusion_reference`。融合核验两边输入、比赛身份、截止时间、矩阵哈希和工件身份；重复工件拒绝计作两个独立专家。不同支持仅补零，完整概率质量保留。来源审查仍依赖已有采集与活动入口，数学融合不补齐缺失证据。

目前融合为**明确未训练的50%当前＋50%test研究参考**，不是最优权重、动态融合晋级或命中率提升。权重与源工件哈希随输出记录，另有总变差和统计第一比分一致性，提示相关性。统计比分、胜平负、单队均值/区间/P0/P2+/P3+来自同一联合矩阵；统计第一比分不冒充独立综合Primary。大小球必须有截止前真实源报价时间，默认最多60秒且完整报价通过原检查，缺失/过期就不计算该盘。

以下不纳入比分概率平均：冷门分类器（标签空间不同）、未通过的ML-0.2及新融合/校准候选、未训练的球员/市场/选择器、其他联赛模型和未核的资产冲突。它们可能保留在原输出为独立状态，不伪造转换成联合比分矩阵。

CLI先在`current-test-pair`轨追加原双模型快照并返回可供综合分析引用的回执，再在`ensemble-research`轨追加融合结果。不会修改旧冻结或`comprehensive`推荐，不更换活动注册表。已有输出路径拒绝覆盖。未知队列、身份不符、无矩阵、哈希不符或已开场输入均拒绝。

真实验收：对本批7场原双模型输出逐一融合，输入未改；本菲卡用真实活动工件重新运行统一CLI并完成独立冻结。其融合统计第一比分2–0，与原综合2–1分开，不用新结果覆盖原推荐。其余特殊路由尚未逐一重跑真实未来比赛，不能声称所有19路由均完成真实融合推理验收。没有新训练、模型晋级或准确率改善证明。
