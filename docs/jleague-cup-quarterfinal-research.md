# 日联杯八强双回合迁移研究

2026-11-11执行用户授权的补齐方案。新增独立入口 `runtime/jleague_cup/quarterfinals.py`，不修改旧edition模型、活动注册表、日职联模型或已经发布的人工判断。

## 已核实的边界

官方历史规则：2022仍以客场进球作为总得失球之后的决胜条件；2023明确撤销，2024/2025明确无客场进球。本届2026/27的官方完整判胜顺序为两场胜数、两场得失球、次回合结束后30分钟加时、点球，不包含客场进球步骤。当前页面没有直接写“取消客场进球”，不能把上述判胜顺序判断说成原文直引。

只允许经主代理复核、附官方原文/URL/查询时间/SHA及正文短摘的机制证书。校验时排除HTML注释和脚本，避免把页面残留的旧规则当正文。机制对齐不等于参赛人群、晋级入口、赛历或球队强度分布相同；2023组赛晋级、2024/25改制以及2026/27入口差异继续列为未验证迁移风险。

历史库存从212场扩至233场，新增2022淘汰阶段21场。八强上下文库含32场：2022年8场排除训练，2023–2025每年8场、合计24场进入本轮研究。各年必须恰好四组对阵、每组首/次回合各一场，日期顺序和主客互换一致。三个有加时/点球标志的历史八强比赛已按原始分段核实90分钟标签。旧数据库保持原样。

本次没有补2021，也没有把2022虽已入库的比赛并进同规则训练。库存仍非全历史完整认证；原始历史first-known未知，场地仍保留NULL，不默认非中立。

## 协议、拟合及诊断

协议在实际训练前冻结：每回合至少12场用于进入探索性拟合，至少8场先前历史用于评估拟合；未来每回合至少30场仅为观察条件，不自动通过。这个小样本研究入口独立于旧edition入口，未降低任何正式验收条件，也未重选参数。

- 首回合和次回合各12场，分别训练当前候选（Poisson截距/显式场地缺失）与test候选（固定ridge=20球队攻防Poisson），共4个新工件。
- 按完整赛季展开时间窗口：先前赛季拟合，后续赛季评价；本次实际可用的是2023/24共8场拟合、2025年4场留出，每回合分别计算。评估核心和全12场重拟合工件分开保存。
- 首回合候选统计Top1：当前1/4、test1/4；次回合两者均0/4。test两回合比分log-loss均未优于基线。4场留出不是可靠的效果验收，也没有未来收益证明。
- 次回合数据保存从本场主队视角的首回合总比分、首回合事件ID和原文；没有使用次回合赛果作为赛前特征。总比分战术影响系数仍未训练，不声称模型已经学习领先后收缩/落后追分。
- 没有训练xG、伤停、当前阵容或实盘盘口通道。历史场地缺失，不能宣称已经学到可靠主场优势。未知球队明确使用拟合总体先验；大阪樱花未出现在这24场训练数据中。

## 研究预测和冻结

官方日文与英文同一比赛页的RSC事件对象绑定球队代码、名称、主客和开球；历史别名映射经审查，不做模糊猜队。当前事件的开球必须与同一个事件对象绑定，不能取页面其他比赛的日期。未来输入拒绝目标比分标签，规则、原始来源、模型依赖与索引哈希均须匹配。

登记本届八强8场完整研究范围。11月11日四场首回合生成独立候选双矩阵并按 `jleague-cup-quarterfinal-candidates` 轨冻结；它们不是活动current/test输出，也不覆盖此前人工综合推荐。11月15日四场次回合只登记范围：实际首回合尚未结束，不生成或冻结其比分预测。后续必须取得已核验首回合90分钟赛果、原文时间及正确主客映射后才能调用。

示例（路径必须替换为实际审查过的输入，新目录拒绝覆盖）：

```bash
python -m runtime.jleague_cup.safe_cli train-quarterfinals \
  --db /absolute/expanded.sqlite --rules /absolute/rules-certificate.json \
  --protocol /absolute/preregistered-protocol.json --out /absolute/NEW-models
python -m runtime.jleague_cup.safe_cli freeze-pairs \
  --index /absolute/NEW-models/candidates.json \
  --fixtures /absolute/verified-future-fixtures.json --out /absolute/NEW-freezes
```

单份 `predict --artifact ... --fixture ... --out ...` 只计算研究输出，不构成已冻结；真实发布使用freeze-pairs。默认独立研究冻结根目录沿用现有WCPP。合成软件测试只能使用临时目录，不能伪装成真实预测。

2026-11-13起新增操作使用上述`safe_cli`兼容入口，单份预测使用`python -m runtime.jleague_cup.safe_cli predict`。旧模型、证据、数据库和八强模块均保留原字节，以继续验证既有工件源码哈希。新入口在首个冻结前检查全批身份、索引及完整依赖哈希、角色与回合、首回合赛果证据，并预先计算所有可发场次的双边结果；缺少首回合赛果的次回合只登记延期。预检结束再次核对来源、时间及输入哈希，任何预检失败均不创建输出目录或冻结记录。每批和每份预测保存执行校验层与旧依赖SHA；这项检查不构成跨文件磁盘事务，也不代表候选通过活动模型验收。

## 验收与下一步

目前结论：**八强首、次回合均已有可运行研究候选；仍无通过验收的活动预测模型。** 正式验收继续检查独立来源、真实赛前时点、完整同场Top1净增、概率质量、胜平负、真实盘口大小球与覆盖率；缺实际线不自设2.5，不借J1或其他杯赛样本。

先结算本批首回合的完整冻结分母，再在次回合赛前补首回合上下文及实盘，追加各自首次有效研究预测。历史开发诊断不是as-of回测，不能用全历史重拟合工件回放已含标签来增加验证样本。每届八强每回合仅4场，未来每回合30场门槛可能跨多个赛季；不承诺短期自动验收。若扩大到半决赛或引入其他赛事特征，必须另行预登记独立实验，不能为凑样本静默混训。
