## 日职联方案：先恢复工程可运行，再验收新候选

1. **P0 身份与依赖修复**：找回test训练当时的匹配源码，在隔离目录重载原工件；若无法恢复，按已锁配方生成新的独立候选并重做验收。不得修改旧工件哈希以绕过完整性校验。建立基于提供方真实球队ID的双侧映射，测试同场身份一致、未知球队拒绝，以及日联杯/百年构想联赛拒绝。验收产物为同一真实未来比赛的两份合法矩阵及实际执行审计，不是模型效果证明。
2. **P1 数据刷新审计**：按J1常规赛/年代隔离核查历史库，补10月10日之后已完成比赛，并与现有11月8日近期事实对照；去重、检查90分钟标签、赛季转换、球队映射和来源时点。不得将百年构想联赛点球结果直接混进常规联赛标签。由Luna在核准预算内采集，主代理验收；当前任务仅给方案，未启动该扩库。
3. **P2 独立固定配方重拟合**：保留当前与test及旧冻结，在新目录按原配方刷新候选。test当前配置为core、半衰期180天、ridge=10、alpha=0；它不等于已训练xG/伤停模块。若尝试新特征/新权重，另开预登记实验，不能与固定配方刷新混称。
4. **P3 验收**：按[OOD边界](asia-leagues-ood-research-tracks.md)和[自主调整规则](autonomous-model-review-policy.md)做时间顺序验证与未来同场冻结对照。报告Primary Top1、胜平负、实际线大小球、覆盖率、净增命中和不确定性；各阶段分离，旧历史缺first-known不认证as-of。只有满足原门槛并验证真实未来增益后才考虑替换；恢复加载不等于效果合格。

## 欧国联方案：保留分级候选，补证据和未来验证

独立库502条合格90分钟历史已用于训练。开发留出结果：A当前/test均2/32；B为3/32与5/32但概率质量退步；C为4/32与3/32；D均2/8且样本不足。不能把B级净增2次比分命中单独包装为通过。

1. 继续保留A/B/C/D、联赛阶段、淘汰/附加赛及首/次回合隔离；无适用工件阶段拒绝，不借俱乐部模型，也不把四级混成一个已验收模型。
2. 对当前历史缺失年份/阶段、原文first-known、场地及升降级球队覆盖做清单核查，先修可验证数据问题。不同国家队世预赛/友谊赛若作为辅助信息，必须另行预登记特征及比赛类型处理，不能直接并成欧国联标签。
3. 沿用[已登记协议](nations-league-model.md)：分级累计未来首次冻结样本，每级至少30场只是观察条件，并非自动通过。已知52场A/B/C各16场、D4场，单批不足；D级需要跨后续比赛窗口积累，不能靠复制样本或并级补数。
4. 在后续真实预测截止前取得实际盘口快照、阵容/征调与可用过程，分别记录使用状态。最初无盘口的冻结不补算实盘指标；新快照和修订独立结算。当前候选仅学习进球/主场/球队攻防，不能声称人员或市场权重已训练。
5. 按完整同场分母审核Top1净增、概率质量、方向/大小球和覆盖率。B级先研究过度自信/正则化/校准，但调整只能在训练/开发区，最终留出及未来批次不用于择优。未通过时保留原基线或继续拒绝活动预测。

本轮未改活动注册表、模型参数或数据库；不承诺达到70%/80%目标。工程修复可明确验证完成时间，欧国联效果验收取决于未来真实比赛数量与表现，不能保证固定日期通过。
