## 已实现

### 成功Current与失败Test可选独立留存

新增显式参数：

```bash
python runtime/predict_active.py FIXTURE.json --registry REGISTRY.json \
  --out NEW.json --freeze-root FREEZE_ROOT --retain-current-on-test-failure
```

默认仍保留原有严格失败行为。只有显式启用且Current已经成功产生合法矩阵，Test的ValueError、OSError或ImportError才被记录为`ABSTAIN_TEST_EXECUTION_FAILED`。不生成替代矩阵，不复制Current当Test，不捕获AssertionError等程序错误。Current自身的身份/范围/工件错误仍阻断，不绕过原验证。

失败轨的概率、第一比分、方向和大小球均为空。完整结果标记`PARTIAL_CURRENT_ONLY`，记录失败阶段、异常类型、Test校验是否实际通过。工件校验阶段失败时引擎标为未执行，预登记哈希不冒充加载成功。补充报告不再重新读取失败/缺失Test工件导致二次失败。

沿用原`current-test-pair`冻结与可恢复发布，不另建一套台账。合成工件通过真实适配器，已测试冻结、首次版本、交付中断后恢复、中文文件路径、无覆盖，以及成功路径的矩阵/Primary保持一致。这不是日职真实工件验收，也没有修改历史记录。

### 请求执行不再冒充盘口可用

`collector.py`现在按history/market分别记录请求数、成功数和受控错误类别。DNS、连接、超时、TLS、HTTP认证/权限/限流/服务错误、无效JSON分开；不存储原始异常文本、响应正文或鉴权头。失败发生时间使用实际失败时间，不回填成批次启动时间。沿用总请求预算和最多一次重试；认证、权限、限流和格式错误不盲目重试。

现有市场适配器只保留原始响应、没有已核验quote_time；因此即使raw成功，也标`RAW_WITHOUT_VERIFIED_QUOTE_TIME`、`verified_quote_count=0`、`market_model_ready=false`。预算耗尽未请求与请求失败分开。不会把空市场当合格盘口，也不从capture伪造quoted_at。

外层`COMPLETED`为兼容旧消费者仍表示请求任务执行完成，新增`status_scope=REQUEST_EXECUTION_NOT_MODEL_READINESS`、`data_status`、`market_model_ready`，终端摘要也输出它们。未改变数据仓库当前定时器固定源码指针；新通道诊断代码尚未部署到无人值守任务。真实盘口覆盖改善仍待来源适配、实际请求和真实赛前采集验收。
