# FMA有界多智能体证据审查

2026-10-30用户授权增加更多智能体。代码：runtime/research/evidence_agents.py。

这是一条独立研究审查侧路，配置五个角色：身份与数据、近期状态/xG、阵容/赛程/战意、市场证据、反方审计。角色不是数值模型，不修改当前/test矩阵、进球率或Primary，不自行给出数值权重和比分。

宿主显式传入caller(request)->record，可对接当前任务提供的智能体工具或已有合适的LLM调用机制；代码本身不发网络、不要求新增apikey或订阅。没有caller时明确返回NOT_RUN_NO_CALLER，不能称智能体已经运行。不同角色只是待执行任务契约，实际完成与否以calls和records为准。

输入为同一冻结证据包：match_id、as_of、kickoff_at、evidence。每条证据含id/source_url/known_at/captured_at/fields；known_at<=captured_at<=as_of<kickoff。模型产生的解释不得重新充当外部事实。来源时间未知的数据不能冒充已证明当时可用。包不接受模型矩阵或修改指令。

四个分析角色第一轮相互不可见，只收到同一证据包的独立副本与同一哈希；审计员收到这些报告后给出指向既有证据字段的异议。最多第二轮，只有被异议指明的角色纠正解释，审计员再审一次；不能改原证据、引入新概率或无限争论。需要新事实时应由宿主另建有时间身份的新证据包，重新发起研究。

最多10次caller调用，无隐式重试；可降低预算或只跑一轮。缺预算、异常、schema不符、假证据ID、时点穿越均有明确状态，不能通过审查自动升级模型。无概率阈值或模型权重在此组件学习。

输出严格限定角色身份、包哈希、状态、观察、异议和纠正。未知字段拒绝；观察必须引用现有证据ID和字段。概率百分数、数字比分及lambda/权重的数字宣称被拒绝，确需讨论原有数值时直接引用证据字段而不在LLM解释里重写。自然语言校验不是语义真伪证明，主代理仍须核查依据。

接受的原记录追加保留。失败记录只留角色、轮次、响应哈希及异常类型，避免把不可信响应或带凭据异常原文带入日志；需要受控原始转录的调用者须自行按既有密钥/快照规则另行保管。程序不将任何审查状态称为预测准确率提升。

软件测试通过合成mock检查独立首轮、证据哈希、时间门禁、输出限权、纠正范围和调用预算；mock不计为真实智能体结果、训练或足球验证。
